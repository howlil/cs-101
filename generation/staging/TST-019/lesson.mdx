> **Masalah:** OpenAPI SYS-008 tampak benar di atas kertas. Bagaimana memastikan server benar-benar mengirim status, header, JSON schema dan error yang dijanjikan?

**Langkah pertama:** lihat tiga operation response maps di contracts/SYS-008/transfer-api.openapi.json. Jangan menciptakan expected response baru hanya karena HTTP RFC mendefinisikannya.

<MentalModel title="API contract test = spec oracle + observed HTTP">

- Expected: status dan schema dari OpenAPI 3.1.1 pada method/path yang tepat.
- Observed: request sungguhan lewat Node HTTP server, lalu baca status, Content-Type, Location dan WWW-Authenticate.
- Error: application/problem+json dengan status body yang sama seperti status HTTP.
- Drift: response yang salah harus gagal, bukan tertutup oleh success path.
- Scope: server adalah **educational in-memory stub** dengan token tetap; tidak ada Spring, database, OAuth atau transfer uang nyata.

## Declared response matrix

| Method/path | Success | Declared errors |
| --- | --- | --- |
| POST /transfers | 201 plus Location | 400, 401, 403, 409, 500 |
| GET /transfers/{id} | 200 | 401, 403, 404, 500 |
| GET /accounts/{id} | 200 | 401, 403, 404, 500 |

**422 Unprocessable Content:** disebut dalam kriteria kurikulum dan RFC 9110, tetapi **belum ada di SYS-008 OpenAPI**. Status ini adalah *contract gap*, bukan bukti pengujian lulus. Perlu revisi kontrak dan implementasi yang disengaja jika 422 akan didukung.

## Live wire test: request, response, assertion

Run with Node 24 at repository root:

~~~sh
node labs/TST-019/http-contract.mjs
~~~

Expected result:

~~~text
http-paths=3
http-roundtrips=10
status-matrix=200,201,400,401,403,404,409,500
negative-mutations=3-detected
422=undeclared
target=local-educational-stub
~~~

Skenario memeriksa success 200/201, invalid amount 400, missing credentials 401, forbidden 403, missing resource 404, duplicate clientReference 409, dan simulated 500. Setiap respons melewati pemeriksaan Content-Type serta subset schema: required fields, tipe primitive, enum, pattern dan optional properties.

Harness juga sengaja membuat tiga respons invalid: status RFC 9457 tidak cocok, 401 tanpa challenge, dan JSON amount berupa number. Ketiganya harus ditolak. Checker tidak mengimplementasikan seluruh spesifikasi JSON Schema atau menguji aplikasi Spring nyata.
