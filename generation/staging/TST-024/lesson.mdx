<LessonStage stage="understand">

> **Masalah:** unit tests lulus, tetapi service sungguhan dapat gagal menyimpan transfer di database atau keliru menganggap provider timeout sebagai REJECTED.

**Mulai:** pisahkan apa yang perlu dijalankan nyata dan apa yang harus tetap diisolasi sebagai fake bank.

<MentalModel title="Real service, real database, fake bank">

- Transfer API berjalan sebagai service Node HTTP, memakai PostgreSQL driver pg.
- PostgreSQL 16 menyimpan transfer PENDING dan providerOutcome ACCEPTED atau UNKNOWN.
- Fake bank adalah proses HTTP berbeda yang menjawab ACCEPTED atau menunda balasan.
- Docker internal network menghubungkan semua proses tanpa published host ports.
- Bukti hasil berasal dari GET API dan SELECT langsung melalui psql.

</MentalModel>

## Dua jalur uji

| Scenario | HTTP | PostgreSQL | Bank requests |
| --- | --- | --- | --- |
| Fake bank accepts | 201 Created | PENDING / ACCEPTED, provider reference | 1 |
| Fake bank replies after deadline | 201 Created | PENDING / UNKNOWN, no reference | 1 |

Provider ACCEPTED tidak membuktikan settlement. Saat timeout, bank dapat sudah menerima request, sehingga UNKNOWN harus direkonsiliasi sebelum retry.

## Real PostgreSQL service-boundary lab

Dengan Docker daemon dan Node/npm, jalankan di repository root:

~~~sh
bash labs/TST-024/verify.sh
~~~

Expected output:

~~~text
service-boundary-network=internal
transfer-success=persisted-accepted
transfer-timeout=persisted-unknown
bank-requests=2
published-ports=0
production-bank-requests=0
tst024-postgres16=verified
~~~

Skrip menyiapkan PostgreSQL 16, real Node transfer service dan HTTP fake bank pada internal Docker bridge, lalu menjalankan dua transfer. Hasil dicek lewat API GET dan psql langsung, diikuti cleanup otomatis seluruh container dan network.

**Batas:** tidak memakai Spring MVC, auth bank, ledger atau pembayaran asli. V3 generator tidak dapat menjalankan Docker, maka receipt unit ini ditandai not-executable; tes integrasi terpisah wajib lulus di CI.
