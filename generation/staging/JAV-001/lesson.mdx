<LessonStage stage="understand">

> **Problem:** aplikasi Java berjalan di IDE, tetapi gagal saat `mvn clean verify` atau `java -jar` di terminal. Kita perlu membuktikan penyebabnya, bukan sekadar mengganti versi dependency secara acak.

**Mulai:** jalankan ketiga perintah berikut pada terminal **yang sama**.

```sh
java -version
javac -version
mvn -version
```

Bandingkan JDK yang menjalankan Maven dengan `javac`. Jika berbeda, periksa `JAVA_HOME`, `PATH`, dan Maven toolchains sebelum menyentuh program.

<MentalModel title="Compile, build, dan launch adalah tiga kontrak berbeda">

- **JDK** menyediakan `javac` dan `java`; **JVM** mengeksekusi bytecode yang berhasil dikompilasi.
- **Compile-time:** `javac` harus dapat menemukan setiap deklarasi tipe yang dipakai source Java.
- **Maven lifecycle:** `clean` menghapus hasil build lama; `verify` menjalankan fase default sebelumnya seperti compile, test dan package.
- **Runtime:** `java` harus dapat memuat semua class yang diperlukan ketika aplikasi berjalan.
- **Executable JAR:** perlu entrypoint `Main-Class` dan runtime classpath yang sesuai; JAR biasa tidak otomatis memuat seluruh dependency pihak ketiga.

</MentalModel>

## Error pertama menentukan lapisan

| Observasi | Fase | Pemeriksaan pertama |
| --- | --- | --- |
| `cannot find symbol` | Compile | Source/import dan compile classpath |
| `invalid target release: 21` | Compile/toolchain | JDK yang digunakan oleh Maven |
| `no main manifest attribute` | JAR launch | `META-INF/MANIFEST.MF` dan Main-Class |
| `NoClassDefFoundError` | Runtime class loading | JAR dan runtime classpath |
| `mvn clean verify` sukses, `java -jar` gagal | Build vs distribution | Verifikasi executable secara terpisah |

Contoh konfigurasi `pom.xml` **untuk proyek Java 21 sederhana**, menggunakan main class `dev.cs101.Main` yang benar-benar ada:

```xml
<properties>
  <maven.compiler.release>21</maven.compiler.release>
  <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
</properties>
<build>
  <plugins>
    <plugin>
      <groupId>org.apache.maven.plugins</groupId>
      <artifactId>maven-compiler-plugin</artifactId>
      <version>3.16.0</version>
    </plugin>
    <plugin>
      <groupId>org.apache.maven.plugins</groupId>
      <artifactId>maven-jar-plugin</artifactId>
      <version>3.4.2</version>
      <configuration>
        <archive><manifest><mainClass>dev.cs101.Main</mainClass></manifest></archive>
      </configuration>
    </plugin>
  </plugins>
</build>
```

Itu adalah **fragmen** yang harus berada di dalam elemen `<project>` POM lengkap. Pastikan nama kelas, groupId, artifactId dan versi sesuai proyek. Plugin JAR ini tidak otomatis menghasilkan fat JAR dengan semua library; jangan mengasumsikan dependency eksternal sudah tertanam.

## Proof lokal: compile vs runtime

Fixture kecil berikut dieksekusi pada **JDK 21**, tanpa Maven atau dependency eksternal.

```sh
java generation/fixtures/JAV-001/BuildDoctorFixture.java
```

Ia memanggil JavaCompiler untuk menghasilkan kegagalan simbol yang disengaja, membuat class valid, menghapus satu class runtime, lalu memulihkannya. Output yang diharapkan:

```text
java-version=21
compile-missing-symbol=failed
runtime-missing-class=NoClassDefFoundError
restored-run=ready
```

**Batas proof:** output tersebut membuktikan Java 21 compiler dan JVM class-loading behavior, **bukan** bahwa Maven `clean verify`, dependency scopes, atau distribusi `java -jar` sudah diuji. Praktik Maven sungguhan berada di Project.

## Project: Build Doctor

<LearningSegments stage="evidence" segments={lessonSegments} />

Buat proyek Maven Java 21 kecil dengan `src/main/java/dev/cs101/Main.java`. Gunakan satu library ketika benar-benar diperlukan (misalnya untuk formatter) dan uji scope salah secara sengaja. Catat **error pertama** dan akar masalahnya, bukan hanya pesan akhir dari Maven.

```sh
mvn -version
mvn clean verify
java -jar target/build-doctor-1.0.0.jar
```

Nama JAR contoh mengikuti artifactId dan versi POM milik lab; sesuaikan bila berbeda. Untuk setiap kegagalan, bedakan salah target release, symbol hilang saat compile, `Main-Class` hilang, dan kelas runtime yang tidak tersedia. Ulangi dari clean workspace, tanpa memakai IDE.
