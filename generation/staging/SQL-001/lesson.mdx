<LessonStage stage="understand">

> **Problem:** database untuk accounts dan transfers harus bisa dibuat ulang dari workspace kosong, tidak bergantung pada GUI, dan hasilnya harus dapat diperiksa lewat enam query yang benar-benar dijalankan.

**Mulai:** gambar dua tabel: accounts dengan account_id sebagai **PRIMARY KEY**, dan transfers dengan transfer_id sebagai **PRIMARY KEY** serta source_account_id dan destination_account_id sebagai dua **FOREIGN KEY**.

<MentalModel title="Data SQL = struktur + aturan + observasi">

- **Table / row / column:** satu row menyimpan fakta dengan kolom bertipe; PRIMARY KEY mengidentifikasi satu baris unik.
- **Foreign key:** sebuah transfer menunjuk akun yang sudah ada. Nama kolom saja tidak menciptakan referential integrity.
- **Schema / search_path:** cs101_sql001 adalah namespace. Nama tabel tanpa kualifikasi dicari melalui search_path sesi.
- **DDL (CREATE):** mendefinisikan schema dan tabel. **DML (INSERT):** menambahkan data. **DQL (SELECT):** mengambil observasi. **TCL (BEGIN/COMMIT):** membatasi transaksi.
- **Repeatability:** CREATE TABLE IF NOT EXISTS dan INSERT ON CONFLICT DO NOTHING mendukung replay fixture, tetapi **bukan** pengganti schema migration dan tidak membuktikan bentuk tabel existing.

</MentalModel>

## Struktur dan enam query yang harus dapat kamu buktikan

| Inspeksi | Objek yang diuji | Hasil dataset contoh |
| --- | --- | --- |
| 1. current_schema() | Schema aktif | cs101_sql001 |
| 2. pg_tables | Tabel yang ada | accounts,transfers |
| 3. COUNT(accounts) | Baris akun | 2 |
| 4. COUNT(transfers) | Baris transfer | 2 |
| 5. information_schema foreign keys | Relasi yang benar-benar dibuat | 2 |
| 6. SUM(amount) WHERE currency='IDR' | Jumlah nominal dengan tipe NUMERIC | 155000.00 |

Gunakan seed transfer **125000.00 IDR** dan **30000.00 IDR**. Jangan menggabungkan nominal dari currency berbeda. Ini sandbox latihan, **bukan** double-entry ledger atau bukti transaksi finansial yang aman.

## Latihan langsung dengan psql

File yang bisa dijalankan tersedia di repositori:

- labs/SQL-001/init.sql — DDL + DML + transaksi dalam schema cs101_sql001.
- labs/SQL-001/inspect.sql — enam SELECT query untuk memeriksa data dan metadata.
- labs/SQL-001/verify-postgres.sh — integration proof terhadap disposable PostgreSQL 16.

Dengan database **sandbox** yang kamu kontrol dan PostgreSQL client terpasang:

~~~sh
psql -X -v ON_ERROR_STOP=1 -d your_sandbox_db -f labs/SQL-001/init.sql
psql -X -v ON_ERROR_STOP=1 -At -d your_sandbox_db -f labs/SQL-001/inspect.sql
~~~

Jalankan init.sql dua kali. Periksa bahwa kedua run menghasilkan jumlah row dan foreign key yang sama. Perintah di atas bergantung pada koneksi/akun PostgreSQL milik environment kamu; jangan arahkan ke database production.

Untuk menjalankan proof end-to-end menggunakan **Docker lokal**:

~~~sh
bash labs/SQL-001/verify-postgres.sh
~~~

Script CI tersebut membuat container PostgreSQL 16 terisolasi tanpa port yang dipublikasikan, menjalankan query, mengulang init, memeriksa fresh database kedua, dan menghapus container setelah selesai.

**Batas generator:** SQL belum didukung oleh runner executable V3 Node/Java. Bundle SQL-001 memakai alasan *not executable in generator* yang eksplisit. Hasil SQL hanya dinyatakan teruji oleh **PostgreSQL integration test terpisah**, bukan oleh validator authoring atau fixture palsu.
