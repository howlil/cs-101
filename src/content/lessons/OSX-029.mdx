<LessonStage stage="understand">

> **Misi:** jelaskan mengapa host bisa memanggil `127.0.0.1:8080` tetapi peer namespace tidak dapat menjangkau API melalui IP veth host.

**Mulai:** prediksi apakah server yang hanya listen `127.0.0.1` akan menerima koneksi ke target `127.0.0.2` dalam satu Linux namespace.

<MentalModel title="Bind address, route, dan netns adalah batas yang berbeda">

- **127.0.0.1**: satu alamat loopback IPv4 di namespace pemanggil.
- **0.0.0.0**: wildcard untuk **binding** ke alamat IPv4 lokal, bukan tujuan koneksi client.
- **ip addr / ip route**: alamat interface dan jalur dalam namespace yang sedang digunakan.
- **ss -lntp**: socket yang benar-benar mendengarkan alamat dan port tertentu.
- **Network namespace**: memisahkan loopback, interface, route, firewall rules, dan socket. Untuk koneksi antar-namespace diperlukan jalur seperti **veth**.

</MentalModel>

<ConceptGraph>


## Diagnostic sequence

```sh
ip -br addr
ip route
ip route get 10.200.30.2
ss -lntp '( sport = :8080 )'
curl --noproxy '*' --connect-timeout 2 http://127.0.0.1:8080/
```

`ip addr` bukan `ss`: interface dapat memiliki IP walaupun aplikasi hanya mendengarkan loopback. `0.0.0.0` memperluas permukaan jaringan; pilih bind ke alamat interface spesifik bila itu sudah cukup. IPv6 harus diperiksa terpisah dengan `ss -lnt4` dan `ss -lnt6`.

### Manual netns lab — VM Linux disposable saja

Perlu hak root/CAP_NET_ADMIN, iproute2, curl dan Node. Command berikut mengubah interface/namespace; **jangan jalankan pada server produksi**.

```sh
sudo ip netns add cs101-peer
sudo ip link add cs101-host type veth peer name cs101-peer0
sudo ip link set cs101-peer0 netns cs101-peer
sudo ip addr add 10.200.30.1/30 dev cs101-host
sudo ip link set cs101-host up
sudo ip -n cs101-peer addr add 10.200.30.2/30 dev cs101-peer0
sudo ip -n cs101-peer link set lo up
sudo ip -n cs101-peer link set cs101-peer0 up
ip -br addr
sudo ip -n cs101-peer addr
sudo ip -n cs101-peer route
```

Di host terminal pertama, buat server loopback:

```sh
node -e 'require("node:http").createServer((q,r)=>r.end("ok")).listen(8080,"127.0.0.1")'
```

Di terminal kedua, bandingkan:

```sh
ss -lntp '( sport = :8080 )'
curl --noproxy '*' --connect-timeout 2 http://127.0.0.1:8080/
sudo ip netns exec cs101-peer curl --noproxy '*' --connect-timeout 2 -v http://10.200.30.1:8080/
```

Hentikan server (Ctrl+C), kemudian coba bind **spesifik** ke host veth IP dan ulangi peer curl:

```sh
node -e 'require("node:http").createServer((q,r)=>r.end("ok")).listen(8080,"10.200.30.1")'
```

Jika masih gagal, telusuri routing, firewall dan state veth; jangan mengarang observasi. Setelah menghentikan server, bersihkan hanya resource lab:

```sh
sudo ip netns del cs101-peer
sudo ip link del cs101-host 2>/dev/null || true
```
