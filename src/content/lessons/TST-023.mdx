<LessonStage stage="understand">

> **Masalah:** klien mengirim page=-1, limit=1000000, isAdmin=true atau Idempotency-Key yang sama dengan amount berbeda. Bahkan error response yang benar tidak cukup jika database sudah berubah.

**Langkah pertama:** definisikan input yang sah dan validasi semuanya sebelum memasuki operasi penyimpanan.

<MentalModel title="Validate first, mutate once">

- GET: page integer positif, limit 1–50; filter/sort wajib allowlisted dan query duplikat ditolak.
- POST: application/json dengan maksimum 1024 byte; hanya lima field transfer yang diizinkan.
- Same key dan same payload: replay 201 yang pertama tanpa transfer baru.
- Same key tetapi different payload: 409 IDEMPOTENCY_KEY_CONFLICT tanpa mutasi.
- Semua input error menggunakan application/problem+json RFC 9457 dengan type/title/status/code stabil.

</MentalModel>

<ConceptGraph>

~~~text
HTTP input
   |
 Query / raw-body constraints
   +-- invalid ---------------------> 400 / 413 / 415
   |
 Typed DTO and allowed fields
   +-- invalid ---------------------> 400
   |
 Idempotency key + fingerprint
   +-- same payload / existing key -> replay original 201
   +-- different payload / key ----> 409
   +-- valid new operation --------> one 201 + one write
~~~

</ConceptGraph>

## Fault matrix

| Input | Response | Additional writes |
| --- | --- | --- |
| Negative page, enormous limit, unsupported sort/filter | 400 | 0 |
| Unknown or repeated query parameter | 400 | 0 |
| JSON larger than 1024 bytes | 413 | 0 |
| Wrong media type | 415 | 0 |
| Missing field, malformed JSON, forbidden property | 400 | 0 |
| Existing key with new amount | 409 | 0 |
| Same key and same body | Cached 201 | 0 |
| First valid POST | 201 | 1 |

The 1024-byte cap and the limit of 50 are explicit lab policies, not universal HTTP or OpenAPI defaults. The example is a sequential Node in-memory API; real concurrent idempotency requires durable transactional enforcement.

## Real HTTP adversarial lab

Dari root repository dengan Node 24:

~~~sh
node generation/fixtures/TST-023/adversarial-api.mjs
~~~

Expected stdout:

~~~text
invalid-requests=21
stable-problem-details=verified
same-key-replay=201
different-payload-conflict=409
created-transfers=1
idempotency-records=1
unauthorized-mutations=0
runtime=local-node-http-only
~~~

Fixture menjalankan 13 kasus query GET invalid, 8 kasus POST invalid, first successful transfer, idempotent replay, key conflict dan inspeksi data GET. Tidak ada permintaan ke bank atau layanan produksi. Semua rejected request memiliki Problem Details yang diperiksa dan tidak membuat transfer.
