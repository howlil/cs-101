<LessonStage stage="understand">

> Java proficiency di materi ini berarti proyek bisa **dibangun, ditest, dipackage, dan dijalankan dari clean checkout tanpa IDE**, lalu perilaku dasar bahasanya bisa lo prediksi.

## Setelah materi ini, lo harus bisa

- menjelaskan alur source → compile → test → package → run;
- memilih Maven phase berdasarkan outcome yang dibutuhkan;
- membedakan primitive value dengan reference ke object;
- membedakan reference identity dan value equality pada object/String;
- menjelaskan efek `null` pada reference;
- memakai record sebagai data carrier sederhana dan memahami equality-nya;
- menghasilkan CLI dengan output deterministik untuk input yang sama.

<MentalModel title="Toolchain dan language model adalah satu rantai">
Source code hanya berguna kalau build contract-nya reproducible. Maven membawa source melewati lifecycle sampai artifact; JVM menjalankan artifact itu. Di dalam program, variable menyimpan **primitive value** atau **reference value**. Prediksi behavior dari dua lapisan ini: apa yang build tool kerjakan, lalu nilai/reference apa yang program operasikan.
</MentalModel>

## Build harus hidup di luar IDE

IDE boleh membantu edit/debug. Tetapi contract build harus berada di repository.

Maven default lifecycle berjalan berurutan. Memanggil phase yang lebih akhir menjalankan phase-phase yang diperlukan sebelumnya.

Untuk materi ini dua command utama:

```bash
mvn test
mvn package
```

`test` menjalankan test. `package` melanjutkan lifecycle sampai artifact distributable seperti JAR.

Target akhirnya bukan “Works on my IDE”, tetapi:

```text
clean checkout
→ mvn test
→ mvn package
→ java -jar ...
→ deterministic output
```

## Primitive vs reference

Java punya dua kategori tipe utama: primitive dan reference.

Primitive seperti:

```java
int count = 3;
boolean valid = true;
double ratio = 0.5;
```

menyimpan primitive value.

Reference variable seperti:

```java
String a = new String("paid");
String b = a;
```

menyimpan reference ke object. Setelah assignment `b = a`, keduanya menunjuk object yang sama.

Ini membuat pertanyaan berikut berbeda:

```java
a == b
a.equals(b)
```

Untuk reference type, `==` membandingkan reference identity. `equals` adalah contract object untuk equality berbasis nilai bila class mendefinisikannya.

## String: immutable dan equality

`String` adalah object dengan value yang tidak berubah setelah dibuat.

```java
String status = "paid";
status.toUpperCase();
System.out.println(status); // tetap "paid"
```

Method menghasilkan String baru; ia tidak memutasi value `status`.

Jangan gunakan `==` untuk menyatakan “text-nya sama”:

```java
String x = new String("paid");
String y = new String("paid");

System.out.println(x == y);      // false
System.out.println(x.equals(y)); // true
```

<Reveal title="Kenapa string literal kadang membuat == tampak benar?">
Runtime dapat memakai kembali reference untuk string literal tertentu. Itu bukan contract untuk content equality. Untuk membandingkan isi String, gunakan `equals`.
</Reveal>

## null hanya berlaku untuk reference

`null` adalah null reference. Primitive biasa seperti `int` tidak dapat menyimpan `null`.

```java
String name = null;
int count = 0;
```

Dereference null gagal:

```java
name.length(); // NullPointerException
```

Mental model yang lebih berguna: setiap reference boundary harus punya contract — **boleh null atau tidak?**

## Record untuk data carrier

Record adalah class khusus untuk aggregate data sederhana.

```java
record Transaction(String id, long amount) {}
```

Record memberi component fields/accessors dan implementasi `equals`, `hashCode`, serta `toString` berdasarkan component values.

```java
var a = new Transaction("tx-1", 100);
var b = new Transaction("tx-1", 100);

System.out.println(a == b);      // false
System.out.println(a.equals(b)); // true
```

Record mengurangi ceremony data carrier, tetapi bukan alasan untuk menghapus domain validation. Constructor tetap bisa memvalidasi invariant.

## Package dan module: jangan dicampur

Package adalah namespace dan organisasi type:

```java
package com.example.ledger;
```

Java module adalah boundary yang lebih besar dengan descriptor `module-info.java`. Materi ini hanya butuh awareness: package name tidak otomatis berarti aplikasi sudah memakai Java Platform Module System.

## Deterministic CLI

Challenge membutuhkan input yang sama menghasilkan output byte-identical.

Contoh sumber nondeterminism yang harus dihindari bila tidak dibutuhkan:

- timestamp “sekarang” di output;
- random value tanpa fixed seed;
- iteration order dari struktur yang contract-nya tidak menjamin order;
- environment-specific path;
- locale/timezone implicit.

Untuk CLI transaksi sederhana:

```text
stdin
↓
parse
↓
domain calculation
↓
stable formatting
↓
stdout
```

Pisahkan diagnostics ke `stderr` bila perlu agar output data tetap punya contract yang jelas.

## Prediksi sebelum menjalankan

Tulis jawaban sebelum mengeksekusi:

```java
int a = 3;
int b = a;
b++;
System.out.println(a);
```

```java
String a = new String("x");
String b = new String("x");
System.out.println(a == b);
System.out.println(a.equals(b));
```

```java
record Id(String value) {}
System.out.println(new Id("1").equals(new Id("1")));
```
