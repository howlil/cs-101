<LessonStage stage="understand">

> **Masalah:** setiap validasi bank dimasukkan ke browser E2E. CI jadi mahal, rapuh, dan error yang seharusnya mudah dicari di API/SQL malah sulit didiagnosis.

**Mulai:** pilih dua perjalanan pengguna yang menghasilkan nilai bisnis nyata dan bukti yang benar-benar terlihat.

<MentalModel title="Two E2E journeys, technical regressions below">

- **E2E smoke 1:** login → view balance; assert nilai saldo milik akun terautentikasi terlihat.
- **E2E smoke 2:** login → transfer → receipt; assert reference transfer unik dan status PENDING terlihat. Receipt bukan bukti settlement.
- **Unit:** rounding/fee calculations. **API:** invalid login, pagination dan malformed JSON.
- **Contract:** provider/consumer amount type drift. **Integration:** idempotency replay dan timeout yang menyimpan UNKNOWN.
- **Smoke** = dua alur penting; **regression** = proteksi luas di seluruh layer; **acceptance** = kriteria hasil yang bisa diamati, bukan sinonim browser.

</MentalModel>

## Test stage decision matrix

| Scenario | Best-fit test stage | Why |
| --- | --- | --- |
| Login → view balance | E2E smoke | Authenticated user navigation plus visible balance |
| Login → transfer → receipt | E2E smoke | Visible confirmation after multi-step user workflow |
| Fee rounding | Unit | Pure arithmetic with deterministic values |
| Invalid login, negative pagination, malformed JSON | API | Request/response contracts and validation |
| Amount schema drift | Contract | Consumer-provider compatibility |
| Same-key payment conflict | Integration | Request replay and persisted state |
| Bank timeout persists UNKNOWN | Integration | Real service, bank stub and PostgreSQL |

**Batas yang disengaja:** CS-101 adalah pustaka materi tanpa login maupun aplikasi bank. Kedua perjalanan ini adalah **rencana pengujian untuk aplikasi bank hipotetis**, belum test browser yang dijalankan. Jangan menambahkan sistem bank atau akun ke CS-101 untuk memenuhi unit pemilihan strategi.

Fixture ini memvalidasi pilihan test strategy secara deterministik: tepat dua E2E, tujuh kasus regression di layer lebih murah, isolasi akun/fixture dan larangan dependency produksi. Negative mutation guards menguji bahwa menambah E2E tidak perlu, menghilangkan receipt, atau menggunakan bank produksi akan ditolak.

**Batas proof:** ini menguji **strategi pemilihan tes**, bukan autentikasi, transfer, browser, screenshot, API live ataupun penerimaan bank produksi. Browser smoke adalah unit lanjutan, TST-026.
