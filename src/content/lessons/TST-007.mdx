<LessonStage stage="understand">

> **Problem:** kalkulasi fee tampak benar untuk input normal, tetapi salah ketika nominal nol, negatif, maksimum, atau tepat di ambang pembulatan. Bagaimana membuat regression tests yang benar-benar mendeteksi perubahan aturan fee?

**Langkah pertama:** buat satu test JUnit Jupiter dengan tiga tahap **Arrange → Act → Assert**, yang membandingkan hasil publik `calculateFee` dengan `BigDecimal` yang tepat.

<MentalModel title="Satu test = satu kontrak perilaku yang terobservasi">

- **Arrange:** buat `FeeCalculator`, principal `BigDecimal` dari string, dan currency code.
- **Act:** panggil `calculateFee(amount, currency)` sekali untuk satu kasus.
- **Assert:** periksa hasil tepat dengan `assertEquals` atau exception tertentu dengan `assertThrows`.
- **Jupiter lifecycle:** `@Test` menandai test; `@BeforeEach` membuat fixture baru sebelum setiap test. Tidak perlu `@SpringBootTest` untuk fungsi Java murni.
- **Maven proof:** `mvn clean verify` menjalankan JUnit lewat Surefire dan menghasilkan laporan test independen dari IDE.

</MentalModel>

## Kontrak FeeCalculator untuk lab

Ini adalah **kebijakan contoh untuk latihan**, bukan tarif perusahaan finansial atau FX conversion. Tarif fee kedua mata uang adalah **1,5%**, jumlah principal valid dari **0 sampai 1.000.000 unit mata uang**, dan rounding fee memakai `HALF_UP`.

| Input | Expected behavior |
| --- | --- |
| IDR 10.000 | fee IDR 150 |
| USD 100.00 | fee USD 1.50 |
| IDR 0 / USD 0.00 | fee nol dengan scale masing-masing |
| IDR -1 / USD -0.01 | `IllegalArgumentException` |
| IDR 1.000.000 / USD 1,000,000.00 | fee valid 15.000 / 15,000.00 |
| Nilai di atas maksimum | `IllegalArgumentException` |
| IDR 33 dan 34 | fee 0 dan 1 |
| USD 0.33 dan 0.34 | fee 0.00 dan 0.01 |
| IDR 1.50 / USD 1.001 | `ArithmeticException` karena principal scale invalid |
| Currency EUR | `IllegalArgumentException`; tidak ada konversi |

Perhitungan memakai `new BigDecimal("0.015")`, bukan `double`. `RoundingMode.UNNECESSARY` memvalidasi jumlah desimal **input principal**; `RoundingMode.HALF_UP` hanya digunakan saat membulatkan fee yang dihitung. `BigDecimal.compareTo` digunakan untuk batas numerik, sedangkan `assertEquals` atas hasil fee juga memeriksa scale output yang menjadi bagian kontrak.

## Jalankan lab unit test tanpa Spring

Repository menyediakan lab Maven mandiri, lengkap dengan `FeeCalculator.java`, `FeeCalculatorTest.java` dan `pom.xml`. Lab menggunakan **Java 21, JUnit Jupiter 5.14.4, dan Maven Surefire 3.5.4**, tidak membutuhkan Spring Boot ataupun database.

~~~sh
java -version
mvn -version
mvn -B -ntp -f labs/TST-007/pom.xml clean verify
~~~

Lihat laporan Maven di `labs/TST-007/target/surefire-reports/`. Jangan menyimpulkan test berjalan hanya dari pesan `BUILD SUCCESS`: periksa nilai **Tests run** dan pastikan jumlahnya nonzero serta tidak ada failures/errors/skipped. CI akan memvalidasi jumlah tepat **20 test** secara independen dari log terminal.

Contoh satu test behavior:

~~~java
@Test
void normalIdrReturnsExactlyOneHundredFifty() {
    assertEquals(new BigDecimal("150"),
        calculator.calculateFee(new BigDecimal("10000"), "IDR"));
}
~~~

Untuk skenario yang wajib ditolak:

~~~java
@Test
void negativeIdrPrincipalIsRejected() {
    assertThrows(IllegalArgumentException.class,
        () -> calculator.calculateFee(new BigDecimal("-1"), "IDR"));
}
~~~

**Batas bukti:** generator V3 hanya mendukung fixture satu berkas Node/Java. Ia menandai JUnit sebagai `not-executable` untuk runner tersebut. **Maven JUnit integration gate** yang terpisah menjalankan test yang sebenarnya; ini bukan simulasi, dan tidak membuktikan akurasi tarif bank nyata.
