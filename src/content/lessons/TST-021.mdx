<LessonStage stage="understand">

> **Problem:** provider transfer mengubah bentuk response tanpa mengubah endpoint. Bagaimana consumer membuktikan bahwa perubahan itu mematahkan data yang benar-benar dibacanya?

**Mulai:** identifikasi empat bagian expectation: status HTTP, amount string, currency IDR, dan error Problem Details ketika transfer tidak ditemukan.

<MentalModel title="Pact = expectation consumer + provider verification">

- **Consumer:** jalankan kode client terhadap Pact mock server, bukan hanya menguji JSON hard-coded.
- **Contract:** Pact mencatat GET transfer success 200 dan transfer not found 404.
- **Provider:** Verifier memutar ulang contract yang sama terhadap Node HTTP provider lokal.
- **Mutation:** ganti satu hal, amount dari JSON string ke JSON number, lalu provider verifier wajib menolak.
- **Batas:** tidak ada backend Spring MVC, autentikasi bank, database, settlement, atau broker eksternal pada lab ini.

</MentalModel>

## Consumer expectation

| Operation | HTTP | Contract fields |
| --- | --- | --- |
| GET /transfers/tr-001 | 200 | transferId, amount string, currency IDR, status PENDING |
| GET /transfers/missing | 404 | Content-Type application/problem+json, type, title, status |

**Kenapa tidak full E2E?** Contract testing membuktikan kecocokan interface yang dipakai consumer. Untuk perubahan JSON type, pengujian provider Pact lebih cepat dan lebih terisolasi daripada men-deploy seluruh bank simulator. Bukan berarti integrasi dan security test bisa dihapus untuk alur pembayaran sesungguhnya.

## Real Pact JS laboratory

Jalankan Node 24 pada root repository:

~~~sh
npm install --prefix labs/TST-021 --no-audit --no-fund --package-lock=false
node labs/TST-021/pact-contract.mjs
~~~

Gunakan Pact JS 17.1.4 yang dideklarasikan oleh lab. Urutan bukti:
- Consumer menjalankan fungsi HTTP client terhadap mock server Pact, menghasilkan file Pact.
- Verifier memutar ulang success 200 dan error 404 terhadap local HTTP server yang sehat.
- Provider kedua mengubah amount string menjadi number; Pact harus mengembalikan verification failure yang *diassert* oleh negative test.

Generator V3 **tidak** mengklaim menjalankan Pact: dependency native dijalankan secara terpisah di CI. Lab menulis kontrak ke direktori sementara, bukan ke database atau file user. Tidak perlu Pact Broker untuk demonstrasi lokal ini.
